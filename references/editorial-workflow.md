# 口播与画面对应

For a narration-led screen tutorial, create a compact edit map before assembling the timeline:

| Output segment | Spoken idea | Screen evidence or presenter | Source and in/out | Caption | Emphasis / sound |
|---|---|---|---|---|---|
| e.g. 00:48–00:54 | Bring personal materials into context | The actual assets and the input area | clip/take timestamps | One current sentence | One grouped asset card |

Use actual spoken content and actual screen operations. When multiple takes repeat a sentence, compare intelligibility, expression, continuity, and usable handles; choose one and note the selected source. Trim dead air and duplicate actions. Preserve natural consonant attacks, breaths, and visual continuity across cuts.

For a narrated instruction, the viewer should see the relevant interface, material, or result while it is discussed. If the screen recording lacks that moment, use the user's genuine source assets in a clearly editorial illustration, or ask for a missing capture when accuracy depends on it. Do not fabricate an operation.

If speed changes are needed, favor stable speed within a spoken passage. Select a modest rate only after listening to the result; excessive variable speed and abrupt transitions make speech sound jumpy. A short room-tone/audio bridge or a visual cutaway can soften necessary edits. Match the presenter video and its voice audio to the same source window and playback rate.

When the user will record narration later, make a temporary timing plan from the script and leave replaceable gaps or markers. Identify that the final sync must be revisited after the real voiceover arrives.

Useful review points: opening promise, each step boundary, every highlighted prompt/result, picture-in-picture entrance and exit, music loop, and final handoff. This is a review guide, not a fixed sequence.
